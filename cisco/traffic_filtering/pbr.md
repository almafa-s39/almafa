# Policy-Based Routing (PBR) Complete Documentation & Examples

## 1. Overview

**Policy-Based Routing (PBR)** is a feature in Cisco IOS and IOS-XE that allows network administrators to make routing decisions based on policies set by the network administrator, rather than relying solely on the destination IP address and the router's global routing table.

While traditional routing forwards packets based purely on where they are going (destination), PBR can forward packets based on where they came from (source IP), what protocol they are using (TCP/UDP), port numbers, or packet size.

---

## 2. Core Components

A PBR configuration relies on matching specific traffic and applying a routing action to it.

1. **Access Control Lists (ACLs):** Defines the "interesting" traffic (source, destination, protocols).
2. **Route-Maps:** Links the ACL to a routing action (e.g., `set ip next-hop`). Processed sequentially.
3. **Interface Application:** Applied inbound on the interface where traffic enters (`ip policy route-map <name>`).

---

## 3. Comprehensive Configuration Examples

### Example 1: Protocol & Destination-Based Routing (Original Scenario)

**Goal:** Route RADIUS (UDP 1812) to `10.20.200.102`, Syslog (UDP 514) to `10.20.200.101`, and all other traffic for `10.20.200.100` to `10.20.200.100`. Apply to `g0/0` and `vlan 999`.

```cisco
! 1. Define ACLs
ip access-list extended ACL-RADIUS
 permit udp any host 10.20.200.100 eq 1812

ip access-list extended ACL-SYSLOG
 permit udp any host 10.20.200.100 eq 514

ip access-list extended ACL-DEFAULT
 permit ip any host 10.20.200.100

! 2. Create the Route-Map
route-map PBR-REDIRECT permit 10
 match ip address ACL-RADIUS
 set ip next-hop 10.20.200.102
!
route-map PBR-REDIRECT permit 20
 match ip address ACL-SYSLOG
 set ip next-hop 10.20.200.101
!
route-map PBR-REDIRECT permit 30
 match ip address ACL-DEFAULT
 set ip next-hop 10.20.200.100

! 3. Apply to Interfaces
interface GigabitEthernet0/0
 ip policy route-map PBR-REDIRECT
!
interface Vlan999
 ip policy route-map PBR-REDIRECT
```

### Example 2: Source-Based Routing (Guest vs. Corporate Traffic)

**Goal:** We have two subnets on the same router. Corporate traffic (10.1.1.0/24) should route out through the primary dedicated WAN (next-hop 192.168.10.1). Guest Wi-Fi traffic (10.1.2.0/24) should be routed out through a cheaper, secondary broadband connection (next-hop 172.16.20.1).

```cisco
! 1. Define ACLs matching the source subnets
ip access-list extended ACL-CORP-TRAFFIC
 permit ip 10.1.1.0 0.0.0.255 any

ip access-list extended ACL-GUEST-TRAFFIC
 permit ip 10.1.2.0 0.0.0.255 any

! 2. Create the Route-Map
route-map PBR-ISP-STEERING permit 10
 match ip address ACL-CORP-TRAFFIC
 set ip next-hop 192.168.10.1
!
route-map PBR-ISP-STEERING permit 20
 match ip address ACL-GUEST-TRAFFIC
 set ip next-hop 172.16.20.1

! 3. Apply to the incoming LAN interfaces
interface Vlan 10
 description Corporate LAN
 ip policy route-map PBR-ISP-STEERING

interface Vlan 20
 description Guest WiFi
 ip policy route-map PBR-ISP-STEERING
```

### Example 3: Reliable PBR using IP SLA (Tracking Next-Hop Reachability)

**Goal:** Route HTTP/HTTPS traffic to a specific web-filtering appliance (10.50.50.5). However, if that appliance goes down, we want to stop blackholing traffic and fall back to the normal routing table. We achieve this by tracking the next-hop using IP SLA.

```cisco
! 1. Setup IP SLA to ping the appliance every 5 seconds
ip sla 1
 icmp-echo 10.50.50.5
 frequency 5
ip sla schedule 1 life forever start-time now

! 2. Track the SLA state
track 1 ip sla 1 reachability

! 3. Define ACL for Web Traffic
ip access-list extended ACL-WEB
 permit tcp any any eq 80
 permit tcp any any eq 443

! 4. Create Route-Map with Tracking
route-map PBR-WEB-FILTER permit 10
 match ip address ACL-WEB
 ! The verify-availability command ties the next-hop to the tracker
 set ip next-hop verify-availability 10.50.50.5 1 track 1

! 5. Apply to Ingress Interface
interface GigabitEthernet0/1
 ip policy route-map PBR-WEB-FILTER
```

### Example 4: Local Policy Routing (Routing Router-Generated Traffic)

**Goal:** Standard PBR only applies to traffic passing through the router. If you want to policy-route traffic generated by the router itself (like local pings, NTP, or Syslog generated by the router), you must use Local PBR.

```cisco
! 1. Define ACL for router-generated NTP traffic
ip access-list extended ACL-LOCAL-NTP
 permit udp any any eq 123

! 2. Create the Route-Map
route-map PBR-LOCAL permit 10
 match ip address ACL-LOCAL-NTP
 set ip next-hop 192.168.100.1

! 3. Apply globally for locally generated traffic
ip local policy route-map PBR-LOCAL
```
