# OSPFv3

Open Shortest Path First version 3 (OSPFv3) is the updated iteration of the protocol designed specifically for IPv6. While it operates on the same fundamental Dijkstra SPF algorithm as OSPFv2, OSPFv3 decouples routing from the interface's global subnet and relies entirely on IPv6 link-local addresses for neighbor communication and next-hop forwarding.

## 1. OSPFv3 Fundamentals & Link-Local Forwarding

Before configuring OSPFv3, IPv6 routing must be globally enabled. A critical difference in OSPFv3 is that the Router ID remains a 32-bit integer (formatted like an IPv4 address). If the router has no active IPv4 interfaces, you must manually define this Router ID, or the OSPFv3 process will fail to start.

**Configuration:**

```cisco
! Enable IPv6 routing globally
ipv6 unicast-routing

! Initialize the OSPFv3 process
ipv6 router ospf 1
 router-id 10.255.255.1

! Enable OSPFv3 directly on the interfaces
interface GigabitEthernet0/0
 ipv6 address 2001:DB8:10:10::1/64
 ipv6 ospf 1 area 0

interface GigabitEthernet0/1
 ipv6 address 2001:DB8:10:20::1/64
 ipv6 ospf 1 area 1
```

**Command Breakdown & Explanation:**

- `ipv6 unicast-routing`: Absolutely mandatory. Without this, the router will not forward IPv6 packets or process IPv6 routing protocols.
- `ipv6 router ospf 1`: Enters the OSPFv3 router configuration mode.
- `router-id 10.255.255.1`: Sets the 32-bit identifier.
- `ipv6 ospf 1 area 0`: Binds the interface to OSPF process `1` and places it in Area `0`.

Link-Local Forwarding Concept:
In OSPFv3, you do not use the `network` command. By enabling it directly on the interface, OSPFv3 immediately begins sending Multicast Hello packets using its auto-generated `FE80::` Link-Local address as the source. Adjacencies are formed strictly over these Link-Local addresses, meaning two routers do not even need to be in the same Global Unicast subnet to become OSPFv3 neighbors!

## 2. Passive Interfaces & Network Types

Similar to OSPFv2, securing the routing domain requires passive interfaces, and optimizing the SPF database requires correctly identifying the Layer 2 network type.

**Configuration:**

```cisco
ipv6 router ospf 1
 passive-interface default
 no passive-interface GigabitEthernet0/0
 no passive-interface GigabitEthernet0/1

interface GigabitEthernet0/1
 description P2P-LINK
 ipv6 ospf network point-to-point
```

**Command Breakdown & Explanation:**

- `passive-interface default`: Stops OSPFv3 Hello packets from exiting any interface, securing the edge.
- `ipv6 ospf network point-to-point`: Placed on the interface level, this disables the DR/BDR election on direct links to speed up convergence.

## 3. OSPFv3 LSAs and Flooding Scope

OSPFv3 completely overhauled the Link-State Advertisement structure. Router and Network LSAs no longer carry IPv6 prefix information; they strictly map the topology. Prefix information is now carried in brand new LSA types (8 and 9). Furthermore, LSAs now have explicit flooding scopes defined in their headers.

### OSPFv3 LSA Types

| LSA Type | Name | Generated By | Description |
| :--- | :--- | :--- | :--- |
| `Type 1` | Router LSA | Every Router | Describes the topology/interfaces of the router, but **NO** prefix information. |
| `Type 2` | Network LSA | DR | Describes routers on a broadcast segment. **NO** prefix information. |
| `Type 3` | Inter-Area Prefix LSA | ABR | Replaces v2 Summary LSA. Advertises internal IPv6 prefixes between areas. |
| `Type 4` | Inter-Area Router LSA | ABR | Advertises the route to reach an ASBR. |
| `Type 5` | AS External LSA | ASBR | Advertises external IPv6 prefixes redistributed into OSPFv3. |
| `Type 7` | NSSA LSA | ASBR in NSSA | Advertises external prefixes within a Not-So-Stubby Area. |
| `Type 8` | Link LSA | Every Router | Advertises the router's Link-Local address and IPv6 prefixes attached to a specific link. |
| `Type 9` | Intra-Area Prefix LSA | Every Router | Associates actual IPv6 prefixes with the topology built by Type 1 and Type 2 LSAs. |

### OSPFv3 Flooding Scopes

| Scope | Applicable LSA Types | Description |
| :--- | :--- | :--- |
| `Link-Local` | Type 8 | Flooded only on the local physical link. Never forwarded by a router. |
| `Area-Local` | Types 1, 2, 3, 4, 7, 9 | Flooded throughout a single OSPF area. Blocked by ABRs. |
| `AS-Wide` | Type 5 | Flooded throughout the entire OSPFv3 routing domain. |

## 4. IPv6 Route Summarization

Summarizing IPv6 routes works conceptually the same as IPv4, drastically reducing the size of the Type 3 and Type 5 LSAs propagated through the network.

**Configuration:**

```cisco
ipv6 router ospf 1
 ! ABR Inter-Area Summarization
 area 1 range 2001:DB8:10::/48
 
 ! ASBR External Summarization
 summary-prefix 2001:DB8:99::/48
```

**Command Breakdown & Explanation:**

- `area 1 range ...`: Configures Inter-Area summarization on the Area Border Router. All subnets falling within the `/48` block from Area 1 will be advertised to the backbone as a single Type 3 Inter-Area Prefix LSA.
- `summary-prefix ...`: Configures External summarization on the Autonomous System Boundary Router before external routes are injected into the OSPFv3 domain.

## 5. OSPFv3 Authentication (IPsec)

Unlike OSPFv2, which has authentication built directly into the OSPF packet header, early OSPFv3 implementations relied entirely on IPv6's native IPsec extension headers (Authentication Header / Encapsulating Security Payload) to secure neighbor adjacencies.

**Configuration:**

```cisco
interface GigabitEthernet0/0
 ipv6 ospf authentication ipsec spi 256 md5 0123456789ABCDEF0123456789ABCDEF
```

## 6. OSPFv3 Verification and Troubleshooting

Because OSPFv3 operates over Link-Local addresses, verifying adjacencies requires careful attention to the interface output rather than global IP addresses.

**Verifying Adjacencies:** `show ipv6 ospf neighbor`

What it checks and variables to look for:

- `Neighbor ID`: The 32-bit OSPF Router ID of the neighbor (e.g., `10.255.255.2`).
- `Pri` / `State`: The DR priority and the adjacency state (look for `FULL`).
- `Dead Time`: Countdown timer for the Dead Interval.
- `Interface`: The local interface connecting to this neighbor.
- `Instance ID`: OSPFv3 allows multiple instances to run on a single link; this confirms which instance the neighbor belongs to (default is 0).

**Verifying Interface Parameters:** `show ipv6 ospf interface brief`

What it checks and variables to look for:

- `Interface`: The physical or logical interface name.
- `PID`: The OSPFv3 Process ID.
- `Area`: The OSPF Area.
- `Intf ID`: The unique Interface ID assigned by the router.
- `Cost`: The IPv6 metric for this link.
- `State`: The role (`DR`, `BDR`, `P2P`).
- `Nbrs F/C`: Fully adjacent vs. Connected neighbors.

**Verifying the Routing Table:** `show ipv6 route ospf`

What it checks and variables to look for:

- `Route Codes`: Look for `O` (Intra-area), `OI` (Inter-area Prefix Type 3 LSA), or `OE1`/`OE2` (External Type 5 LSA).
- `IPv6 Prefix`: The destination network.
- `[110/Cost]`: Administrative distance (110) and the cumulative IPv6 path cost.
- `Via`: The next-hop address. **Crucially, this will always be an `FE80::` Link-Local address, not a global unicast address**, followed by the exit interface.

**Verifying the Link-State Database (LSDB):** `show ipv6 ospf database`

What it checks and variables to look for:

- `Link (Type-8) Link States`: Shows the local link prefixes and Link-Local addresses.
- `Intra Area (Type-9) Link States`: Shows the actual IPv6 prefixes associated with the Router and Network LSAs.
- `ADV Router`: The 32-bit Router ID of the device that generated the specific IPv6 LSA.
- `Age` / `Seq#`: The age in seconds and the hexadecimal sequence number to track LSA freshness.
